# AGENTS.md

## Stack

- **Bun monorepo** (bun@1.3.3) — `apps/*` and `packages/*` workspaces
- **SvelteKit** web app (`apps/web`) — Svelte 5, TailwindCSS v4, bits-ui (shadcn/ui)
- **mdsvex** for markdown blog posts in `apps/web/src/posts/`
- **@yet-another-portfolio/config** — shared tsconfig base
- **@yet-another-portfolio/env** — t3-oss/env-core + zod env validation (currently stub)

## Commands

```bash
bun install              # install deps (isolated linker, see bunfig.toml)
bun run dev              # start all apps
bun run dev:web          # start web app only (vite dev server, port 5173)
bun run build            # build all apps
bun run check-types      # typecheck all packages
```

Web-specific (from `apps/web/`):
```bash
bun run check            # svelte-kit sync + svelte-check (primary type checker)
bun run check:watch      # same, in watch mode
```

## Type checking

- Root tsconfig extends `@yet-another-portfolio/config/tsconfig.base.json`
- Web tsconfig extends `.svelte-kit/tsconfig.json` (generated by SvelteKit)
- Strict mode: `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`
- There is **no linter or formatter** configured — type checking via `svelte-check` is the main gate

## Project structure

```
apps/web/src/
  routes/           # SvelteKit routes (+page.svelte, blog/[slug]/)
  lib/
    config.ts       # Aggregates all site data into siteConfig
    data/           # Content: projects, experience, education, interests, schemas
    components/     # Svelte components (Hero, Career, ProjectCard, phone/, etc.)
    stores/         # Svelte stores (theme, ui, chat)
    actions/        # Svelte actions (sticky)
  posts/            # Markdown blog posts (processed by mdsvex)
static/             # Static assets (images, resume PDF, audio)
```

## Content & data

All portfolio content is defined in `apps/web/src/lib/data/` — TypeScript files exporting typed objects (validated by Zod schemas in `schemas.ts`). The main entry point is `siteConfig` in `lib/config.ts`.

To add/update projects, experience, etc., edit the corresponding file in `data/`.

## Conventions

- Use `$lib` alias for imports within the web app (SvelteKit convention)
- Theme colors via CSS custom properties (`--bg-color`, `--text-primary`, `--accent-1`, etc.) — toggled by `.dark` class on `.app-layout`
- Prefer declarative code; avoid unnecessary complexity
- TailwindCSS for styling; avoid inline styles unless necessary
- Short, single-responsibility functions; early returns over nested blocks
- No comments unless logic is non-obvious
- No unused imports or dead code

## Gotchas

- `dev:native` script references a `native` filter that doesn't exist in `apps/` — ignore it
- `.svelte-kit/` is generated — don't edit files inside it
- The env package (`@yet-another-portfolio/env`) exports `./web` but the schema is currently empty
- `bunfig.toml` uses `linker = "isolated"` — don't change this without understanding bun's linker implications
